\begin{abstract}\noindent
A robot revisiting a room with a map from an earlier visit must (i)~find its pose in that map without an initial
guess, (ii)~decide which objects stayed, moved, appeared or disappeared, and (iii)~edit the map accordingly. We pose
this as a joint relocalization and change-detection problem on object-level 3D scene graphs and propose a
training-free pipeline whose core is a pairwise distance-consistency test: objects that did not move keep their
mutual distances, so the largest mutually consistent set of object matches is the static set and yields the pose,
while smaller consistent sets are objects that moved together. This report covers Phase~1. We formalize the problem,
review the literature, implement graph construction on 3RScan/3DSSG and Steps~1--3 (candidate matching, maximum
consistent set, pose), and evaluate relocalization against four baselines under one protocol in which the new visit is
moved by an unknown rigid transform. On a 17-pair validation subset our method relocalizes 82.4\% of pairs at the
RIO threshold (20\,cm/20$^\circ$) in 0.13\,s per pair, invariant to the transform. The learned scene-graph aligners
SGAligner and SG-PGM fall to 35\% and 18\% (from 71--76\% and 65\% when frames are pre-aligned), while dense
FPFH+RANSAC reaches 94\% at 37$\times$ our runtime.
\end{abstract}

\section{Problem statement}\label{sec:problem}
\paragraph{Map and observations.} A map is an object-level 3D scene graph $\G^{M}=(\mathcal{V}^M,\mathcal{E}^M)$ in a
fixed map frame. Each object node $o\in\mathcal{V}^M$ stores its points $P_o\subset\R^3$, centroid $\ci_o$, extents
$\mathbf{e}_o$, class $\ell_o$, height above the floor $h_o$ and change history; structural nodes hold floor and walls;
edges carry support/spatial relations. A visit produces a point cloud split into segments, from which we build
$\G^{N}=(\mathcal{V}^N,\mathcal{E}^N)$ in the robot's own frame, related to the map frame by an unknown
$\T^{\star}\in\SE$ (no initial guess, no odometry between visits).

\paragraph{Goal.} Given $\G^M$, $\G^N$ and the visit's depth images, estimate
\begin{enumerate}
  \item the pose $\hat\T\in\SE$ such that $\hat\T\,\ci_{o'}\approx\ci_o$ for every unchanged object pair $(o,o')$, or
        report failure ($\bot$) when the observation cannot determine it;
  \item a partition of the objects into \emph{static} $S\subset\mathcal{V}^M\times\mathcal{V}^N$ (one-to-one matches),
        \emph{moved} groups $\{(M_k,\T_k)\}$ with their rigid motions, \emph{removed} $R\subset\mathcal{V}^M$,
        \emph{added} $A\subset\mathcal{V}^N$ and \emph{not observed} $U\subset\mathcal{V}^M$, where $R$ and $A$ require
        evidence of free space and everything else unexplained goes to $U$;
  \item the updated map $\G^{M'}$ obtained by editing $\G^M$ per object, so that object identities persist and
        $|\G^{M'}|$ grows with the number of objects, not the number of visits.
\end{enumerate}
Over a sequence of visits $t=1,\dots,K$ the map is the result of applying this update repeatedly.

\paragraph{Phase 1 sub-problem.} With segments from 3RScan/3DSSG annotations, solve (1) and the static part of (2):
return $(\hat\T,S)$ or $\bot$. A pair counts as relocalized if $\angle(\hat{\mathbf{R}},\mathbf{R}^\star)\le\tau_r$ and
$\|\hat{\mathbf t}-\mathbf t^\star\|\le\tau_t$ with the RIO thresholds $(\tau_t,\tau_r)\in\{(10\,\mathrm{cm},10^\circ),
(20\,\mathrm{cm},20^\circ)\}$~\cite{wald2019rio}; $\bot$ counts as a failure. We also report registration recall
(RMSE of the visit's points $<0.2$\,m, the criterion of~\cite{sarkar2023sgaligner,xie2024sgpgm,liu2025sgreg}) and
runtime.

\section{Literature review}\label{sec:related}
\paragraph{3D scene graphs.} Armeni~et~al.~\cite{armeni2019scenegraph} introduced layered 3D scene graphs;
Kimera~\cite{rosinol2021kimera} and Hydra~\cite{hughes2022hydra} build them online from SLAM, with objects assumed
static and only agents moving. 3DSSG~\cite{wald2020learning} annotates every 3RScan scan with an object-level graph
(534 classes, 41 relations) and learns to predict it; SceneGraphFusion~\cite{wu2021scenegraphfusion} predicts graphs
incrementally from RGB-D, and ConceptGraphs~\cite{gu2024conceptgraphs} attaches open-vocabulary features to object
nodes. Their update rules either assume a static world or delete objects that are not re-detected, irrespective of
whether they were in view. We reuse this representation but make the per-visit edit explicit and evidence based.

\paragraph{Scene-graph alignment and relocalization.} RIO~\cite{wald2019rio} introduced 3RScan and object instance
re-localization across rescans. X-View~\cite{gawel2018xview} localizes with semantic graphs built from views.
SGAligner~\cite{sarkar2023sgaligner} learns multi-modal node embeddings (point cloud, relations, attributes), matches the
top-$K$ nodes and registers the matched objects with GeoTransformer~\cite{qin2022geotransformer} and
GC-RANSAC~\cite{barath2018gcransac}. SG-PGM~\cite{xie2024sgpgm} casts alignment as partial graph matching, fuses
point-level backbone features into nodes, and re-scores point correspondences with node matches. SG-Reg~\cite{liu2025sgreg}
targets generalization and efficiency with a lighter network and a robust back-end, SGAligner++~\cite{singh2025sgalignerpp}
adds language features, and OpenSGA~\cite{chen2026opensga} moves to open-world graphs. All of these are trained, report
node matching and registration on sub-scans cut from the same scan, and ignore unmatched objects, so they do not output
changes. ROMAN~\cite{peterson2025roman} aligns open-set object maps for global localization using
CLIPPER~\cite{lusk2021clipper}, the closest training-free relative of our Step~2.

\paragraph{Consistency-based data association and robust registration.} Joint compatibility~\cite{neira2001jcbb} and
PCM~\cite{mangelson2018pcm} select the largest set of mutually consistent measurements (PCM via a maximum clique for
loop closures between maps); CLIPPER~\cite{lusk2021clipper} relaxes it to a weighted dense subgraph;
TEASER~\cite{yang2021teaser} and maximal-clique registration~\cite{zhang2023maxclique} apply the pairwise-invariant test
to point correspondences. Classical global registration pairs FPFH features~\cite{rusu2009fpfh} with
RANSAC~\cite{fischler1981ransac} and refines by ICP~\cite{besl1992icp,chen1992pointplane}. We lift the pairwise test from
points to objects, which shrinks the problem from thousands of correspondences to tens and makes the consistent sets
semantically meaningful (static set vs.\ objects moved together).

\paragraph{Change detection and long-term mapping.} Objects Can Move~\cite{adam2022objects} detects moved, added and
removed parts between two aligned scans by geometric-transformation consistency, producing unlabelled clusters.
Living Scenes~\cite{zhu2024livingscenes} relocalizes and reconstructs multiple objects across 3RScan rescans, again given
the scan alignment. DSG~\cite{liao2026dsg} labels objects stable/appeared/missing with Gaussian renderings and an LLM using
ground-truth poses and has no ``moved'' state; 3D VSG~\cite{looper2023vsg} predicts change likelihood without verifying it.
Panoptic Multi-TSDFs~\cite{schmid2022panoptic} and Khronos~\cite{schmid2024khronos} maintain consistent object-level
volumetric maps in changing scenes within one SLAM session, and LT-mapper~\cite{kim2022ltmapper} handles LiDAR
lifelong mapping with change detection after alignment. \Cref{tab:capabilities} summarizes the gap: no method jointly
relocalizes without an initial guess, labels per-object changes with free-space evidence and edits a persistent
map over many visits without training.

\paragraph{Graph construction (done).} We load the annotated instance PLY, semantic labels and 3DSSG relations of each
3RScan scan. Floor, wall and ceiling segments become structural nodes; every other segment with $\ge50$ points becomes an
object node. A floor plane $(\mathbf n,d)$ is fitted to the floor segment and oriented towards the scene. Extents are
pose invariant: the vertical extent along $\mathbf n$ and the two horizontal extents of the minimum-area bounding
rectangle of the footprint (rotating calipers on its hull; PCA axes were unstable for square footprints, caught by a
unit test), all as 2--98\% percentile ranges. Edges are 3DSSG relations plus proximity edges (gap $<0.3$\,m).
\Cref{fig:graphs} shows the two graphs of one pair.

\paragraph{Step 1: candidate matches (done).} For map object $a$ and visit object $b$ of the same class,
\begin{equation}
  \kappa(a,b)=\sum_{k=1}^{3}\bigl|\log(e_{a,k}+\epsilon)-\log(e_{b,k}+\epsilon)\bigr|+\frac{|h_a-h_b|}{\sigma_h},
  \qquad \epsilon=5\,\mathrm{cm},\ \sigma_h=0.3\,\mathrm{m},
\end{equation}
and $\kappa=\infty$ across classes. Each map object keeps its $k=3$ cheapest visit objects and vice versa (if
$\kappa\le2.5$). Nothing depends on the robot's pose; identical objects deliberately receive several candidates, and the
choice among them is left to geometry in Step~2.

\paragraph{Step 2: largest consistent set (done).} Two candidates $m=(a,b)$ and $m'=(a',b')$ are compatible if they are
one-to-one ($a\ne a'$, $b\ne b'$) and
\begin{equation}
 \bigl|\,\|\ci_a-\ci_{a'}\|-\|\ci_b-\ci_{b'}\|\,\bigr|\le\tau_{mm'}\ \ \text{and}\ \
 \bigl|(h_a-h_{a'})-(h_b-h_{b'})\bigr|\le\tau_{mm'},\qquad \tau_{mm'}=\varepsilon+\beta\,(r_m+r_{m'}),
\end{equation}
with $\varepsilon=0.1$\,m for sensor/annotation noise and $\beta=0.1$ scaling with the object radii $r$ because the
centroid of a partly observed large object shifts. The height test rejects mirror-symmetric solutions that preserve all
distances. The static set $S$ is the maximum clique of the compatibility graph (igraph; ties broken by summed
$\kappa$). Removing $S$'s objects and re-solving yields further cliques of size $\ge2$, candidate groups of objects
that moved together, which Step~4 will verify. \Cref{fig:consistency} shows the test on all candidate pairs of the validation
subset: it keeps 94.5\% of pairs between correct, unchanged matches and 25.6\% of the rest; the clique removes the
remainder, since a wrong match must be consistent with \emph{every} member of $S$.

\paragraph{Step 3: pose (done).} With $|S|\ge3$ and non-collinear centroids (second singular value of the centred
centroids $\ge0.2$\,m$\cdot\sqrt{|S|}$) we solve
\begin{equation}
  \hat{\mathbf R},\hat{\mathbf t}=\arg\min_{\mathbf R,\mathbf t}\sum_{(a,b)\in S}w_{ab}\|\mathbf R\ci_b+\mathbf t-\ci_a\|^2
  +\lambda\,\|\mathbf R\,\mathbf n^N-\mathbf n^M\|^2,\qquad w_{ab}=(0.1+\max(r_a,r_b))^{-1},
\end{equation}
in closed form (weighted Kabsch/Umeyama~\cite{umeyama1991} with the floor normals as an extra direction pair), then
refine with point-to-plane ICP~\cite{chen1992pointplane} on the points of $S$ and the structural nodes (5\,cm voxels,
correspondence radius $0.3\to0.1\to0.05$\,m). If $|S|<3$, the centroids are collinear, or the ICP fitness is below
0.3, we return $\bot$. On the development rooms, allowing collinear sets (made solvable by the floor normal) only added
wrong poses: the collinear sets were objects moved together, so the test stays.

\paragraph{Engineering.} The code (\texttt{lifelong/}, $\sim$600 lines of Python) has unit tests on synthetic rooms
(pose invariance, duplicate objects, a jointly moved group, declining). All thresholds were chosen on 6 \emph{training}
rooms (22 pairs); a sweep over $\varepsilon,\beta,k$ and the cost gate gave 19/22 correct and 0 wrong poses almost
everywhere, so results are not sensitive to them.

\section{Experiments}\label{sec:experiments}
\paragraph{Data and protocol.} 4 validation rooms of 3RScan~\cite{wald2019rio} with 3DSSG~\cite{wald2020learning}
(17 reference$\to$rescan pairs; 11--34 objects per map, 6--32 per visit; 81 moved, 11 removed and 3 deformed instances
in total). For each pair the rescan is moved by a stored random transform (uniform rotation in $\SE$, translation
$\mathcal U(-2,2)^3$\,m) and every method receives exactly these points; $\T^\star$ comes from the 3RScan alignment and
is used only for scoring. A second run gives the rescan already aligned to the map, the setting of the learned
baselines' training and evaluation.

\paragraph{Baselines.} We selected the strongest methods with runnable 3RScan code:
SG-PGM~\cite{xie2024sgpgm} and SGAligner~\cite{sarkar2023sgaligner} with their released 3RScan-trained checkpoints (rooms
are from the validation split, so there is no train/test leakage); FPFH~\cite{rusu2009fpfh}+RANSAC and
FPFH+TEASER++~\cite{yang2021teaser} (training free, both with ICP). SG-Reg~\cite{liu2025sgreg} (only a ScanNet-trained
model and a C++ back-end released) and SGAligner++~\cite{singh2025sgalignerpp} (no code) are cited from their papers. Our
adapter exports the pairs into SGAligner's data layout and runs its unmodified preprocessing; SG-PGM reads the same
files. Two fixes were needed for a fair run: GC-RANSAC in SGAligner requires correspondences sorted by score for its
PROSAC sampler (unsorted input returned no model in 53\% of aligned pairs), and FPFH normals are oriented towards the
scan centre (Open3D's default sign depends on the frame, which halved TEASER++'s success under rotation).

\paragraph{Results.} \Cref{tab:results,fig:curves} give the comparison.
(i)~\emph{Invariance.} Ours scores identically with and without the random transform. The learned aligners collapse
(SGAligner 71--76\%$\to$35\%, SG-PGM 65\%$\to$18\%): their node encoders consume object points in world coordinates,
and SG-PGM's published random-transform evaluation rotated only the registration points, not the scene-graph objects.
(ii)~\emph{Accuracy and cost.} Ours matches FPFH+TEASER++ and trails FPFH+RANSAC by two pairs, at 37$\times$ lower cost:
Steps~1--2 take 1.5\,ms on 4--77 candidates, ICP the remaining 0.13\,s. ICP halves the error of the centroid-only pose
(7.6$\to$3.3\,cm) and raises succ.\@10/10 from 53\% to 71\%. Unlike the point-level methods, ours also returns the
object correspondences (static-set precision 60.5\%, recall 58.5\% against unchanged instances; most ``errors'' are
swaps among identical objects, or objects with small motions listed as changed, which do not hurt the pose).
(iii)~\emph{Failures} (\cref{fig:perpair} in the appendix). One café room has a row of identical table--chair--menu sets:
shifting by one set gives a consistent group of 8 objects against 7 for the true one, and with no walls in the scan ICP
cannot tell; RANSAC also fails one of its two pairs. One rescan sees only 6 objects and we decline (RANSAC succeeds
on walls and floor). On the development rooms the remaining declines are rooms in which \emph{every} object moved, for
which declining is the correct object-level answer, but where structure-only registration would still give the pose.
